# Business and system flows

Describe **how scenarios unfold over time** across users, UI, services and state changes. Examples include Backoffice login, media upload/attachment, product publishing and order fulfillment.

Use sequence diagrams for interactions and flowcharts/state diagrams for processes and lifecycles. Identify triggers, participants, main steps, error paths and relevant contracts when known. Clearly distinguish planned from implemented behavior.

**Boundary:** [Architecture diagrams](../03-architecture/diagrams/README.md) describe *what components exist and how they connect*; flows describe *what happens and in what order*. [ADRs](../03-architecture/adr/README.md) explain *why decisions were made*. Link to [machine-readable contracts](../../contracts/README.md) rather than duplicating them.
